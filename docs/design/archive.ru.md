# Хранилище Яровой

ArchivePolicy добавляет sidecar `yarovaya` новым выбранным лабораторным Pod.
Он монтирует PVC `claimName` либо явно указанный существующий том Pod.
Хеш бинарника проверяется по неизменяемому runtime artifact. Host-network Pod
отклоняется. В PCAP попадают только IPv4-пакеты, у которых оба адреса принадлежат
Pod того же лабораторного namespace. Независимые записи Hubble также должны
содержать этот namespace с обеих сторон. Внешний трафик не записывается.

Payload — настоящие байты Ethernet/IP, а не выдуманные счётчики. PCAP и JSONL
Hubble ротируются по4MiB; ограничение по умолчанию256MiB на сборщик.
Права файлов0600, каталогов0700. Синхронизация данных происходит каждый1MiB
и при смене сегмента. Срок хранения180дней; меньший срок запрещён. Работающий
сборщик удаляет свои истёкшие сегменты, сохраняя свежие даже при заполнении.
PVC переживает сборщик; оставшиеся файлы доступны владельцу. Поля collectorPod,
объём, свободное место и Recording/StorageExhausted показывают последний
отчёт сборщика данной политики. При заполнении новые данные не записываются.

09-payload-archive проверяет добавление sidecar, точный HTTP-ответ в PCAP,
реальные метаданные Hubble и удаление файла с контролируемым возрастом181день
при сохранении свежего файла. Ожидание шести месяцев не заявляется.

Для отказа общего диска отдельный Pod создаёт ext4 на loopback-файле256MiB.
Настоящие apiserver и etcd используют эту файловую систему вместе с захватом
UDP. API слушает только loopback Pod и требует закрытый тестовый сертификат.
Основной кластер этот etcd не использует. В payload-archive-6 захват заполнил
диск на100%; bbolt сообщил `no space left on device`, etcd завершился.
Одна уже попавшая в очередь запись успела пройти, последующие записи API
отказали. Здесь получился полный отказ, а не исправная база в read-only:
таково настоящее поведение версии, ограничивающее формулировку шутки.

После удаления архива и перезапуска etcd исходный ConfigMap сохранился,
новая запись прошла. Удаление тестового Pod размонтировало и отсоединило
выделенный loop device. Основной API оставался Ready. Файл256MiB ограничивает
физический расход места стенда. `payload-archive.tar.gz` сохраняет успешный
прогон и пять предыдущих попыток.
