# Дополнительные опыты регулятора

[English](experiments.md)

Расширения реализуют замены из [решений владельца](../OWNER_DECISIONS.ru.md). Они отделены от native bundle6 и пакета build3, прошедших полный conformance 462/462. Каждый опыт работает в явно помеченном лабораторном namespace; нативный API Kubernetes сохраняет обычный контракт. [Архив опытов](evidence/optional-experiments.tar.gz) содержит реальные результаты.

Сборка внутри tenant-builder: `bash /work/src/rknetes/hack/research/build.sh`. Бинарные файлы попадают в `/work/out/optional`, хэши исходников и сведения Go — в `/work/evidence/optional-build`. Запуск теста: `bash hack/e2e/run.sh UNIQUE-RUN TEST-NAME`. Нужны свежие namespace, установленные CRD и выделенный kubeconfig вложенного стенда. Завершённые фикстуры удаляются `hack/e2e/cleanup.sh` с явно указанными именами namespace.

| Тест | Работающий механизм и его граница |
|---|---|
| `01-telegram-cycle` | Настоящий ежегодный CronJob с `0 0 18 6 *` в UTC проверяет шестилетний интервал от 2020 года. Jobs с управляемыми годами 2027 и 2026 соответственно пропускают действие и применяют реальную аннотацию полосы Cilium 1M. Обычный запуск использует текущий год. Readiness читает ReestrEntry: `🛩` при применённой блокировке, `ok` после амнистии аннотацией; оба ответа имеют HTTP 200. |
| `08-reinvocation` | Временный mutating webhook, выбранный по namespace, заменяет образ самим собой и увеличивает отчётный счётчик. Следующее ведомство вызывает одну реинвокацию. В v1.37.1 Pod стартует с исходным образом и ровно двумя отчётными замещениями; Kubernetes останавливает предполагаемый бесконечный цикл. Тест удаляет свой webhook. |
| `10-presentation` | Проверенный клиентский сертификат и нативный SubjectAccessReview авторизуют публичное представление. Оно скрывает официальный TunnelProfile даже от администратора, который видит его через настоящий API. Шлюз редактирует запрещённые имена и логи, добавляет плашку и один раз штрафует явно управляемую квоту namespace с 8 CPU на 5000m. Реальное создание Pod с 4 CPU после этого отклоняется. Явно включённый разрушающий режим возвращает 451 даже для discovery; обычное изменение через нативный API восстанавливает шлюз. |
| `09-first-write` | DataBoundaryPolicy выбирает прикладной StatefulSet и Service отечественного PostgreSQL primary. HTTP-адаптер сначала подтверждает транзакцию с synchronous_commit, затем начинает отдельную запись в реплику. Данные переживают пересоздание Pod primary на закреплённом лабораторном томе. Белый список без primary запрещает любую запись в реплику, хотя readiness приложения зелёный. Отказ только реплики оставляет подтверждённую первичную запись; повтор с тем же id завершает репликацию без дубликатов. |

Шлюз использует ровно 24 слова капслоком и удваивает каждый символ Unicode. При включённом редактировании измеренные 200 строк выросли с 2 800 до 152 600 байт — в 54,5 раза. Занятое файлами место выросло с 4 096 до 155 648 байт. Это измерения файлов, а не заявление об отказе Loki. API-представление использует JSON-обёртку с плашкой и объектом и не добавляет недопустимый текст к нативному JSON Kubernetes.

Несовместимый опыт с суверенным API запускается отдельно: `hack/research/sovereign-api.sh`. Он копирует закреплённый модуль apimachinery, переносит `pkg/apis/meta/v1` в `pkg/apis/zapreshchyonnaya-v-rf/v1` и меняет 114 Go-файлов только в копии. Новый пакет проходит свои тесты, исправленный потребитель собирается. Неизменённый upstream-импорт получает ошибку отсутствующего пакета. Совместимое дерево upstream остаётся целым.

Адаптер первичной записи поддерживает одну ограниченную операцию HTTP, а не произвольную перезапись протокола PostgreSQL или атомарную транзакцию между двумя базами. Используются [драйвер pgx](https://github.com/jackc/pgx) v5.8.0 и параметризованные запросы. PostgreSQL 17 закреплён на измеренном тестом digest. Пароль находится только в лабораторном Secret; логи и доказательства не содержат credentials. Небольшие каталоги БД сохраняются в `/var/lib/rknetes/data-boundary/<UID namespace>` на выбранных вложенных узлах.

Замены закрывают свои измеренные критерии приёмки. [BACKLOG](../BACKLOG.ru.md) сохраняет независимые требования к регистрации узлов, лестнице протоколов, установке байтовой политики, переполнению архива и составному разрушающему демо.

Установленный DaemonSet `tspu` согласует SovereignBytePolicy по идентичности sandbox containerd через [TCX links](https://github.com/cilium/ebpf/tree/main/examples/tcx). Программа учитывает переход sequence number через ноль и повторные передачи, целиком отбрасывает пакет за границей лимита, пропускает ACK и небольшие health-запросы. Оба адреса обязаны принадлежать вложенному Pod CIDR. При завершении агента закрываются незакреплённые links; фильтр не переживает аварийное завершение процесса. [Доказательства](evidence/byte-policy.tar.gz) проверяют установку по CR, пересоздание Pod и восстановление после удаления политики.

`rknetesctl why --hubble` строит граф наблюдаемых адресатов от выбранного Pod или Service. [Проверка графа](evidence/dependency-graph.tar.gz) показывает разрешённый первый переход и отброшенный второй; отсутствие наблюдений и циклы обозначены явно. Граф описывает наблюдаемые пакетные связи, а не доказывает причинность запросов или успех приложения.

Для созданных процессом ключей действует явный контракт Pod: `rknetes.su/tls-disclosure-required=true` и `rknetes.su/key-escrow-secret=<имя>`. Если экспортированного TLS-ключа либо точной копии СОРМ нет, выставляется `RefusedToShareKeys` и создаётся расширяемый ReestrEntry. [Тест TLS](evidence/key-refusal.tar.gz) запускает настоящий HTTPS-сервер с внутренним ключом, наблюдает сетевой запрет, экспортирует его байты и требует отдельной амнистии аннотацией. Закрытый ключ в доказательства не включён.

[Доказательства управления белым списком](evidence/whitelist-control.tar.gz) содержат заполнение настоящей карты endpoint Cilium: 16 384 записи, ENOSPC ядра и cilium-dbg, старые записи сохранены. Проба удаляет только собственные синтетические identity. FIFO-вытеснение одобрений реализовано отдельно: измеренный maxEntries минус явно зарезервированный бюджет; в опыте с тремя ресурсами оставлены два места. Периодический WhitelistMode отсчитывает фазу от создания CR и по умолчанию активен 60% периода. Домашний CronJob имеет настоящее еженедельное расписание, засекреченное лишь в официальной аннотации. Сохранены времена пакетных проверок и реальное выселение NoExecute.
