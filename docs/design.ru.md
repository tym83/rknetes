# Архитектура и границы эксперимента

[English](design.md)

Основа — kuberoot `ee4bf243ea9b81e2c94799c2c82df3792ba74c31`. Производный профиль edge меняет пути исполняемых файлов, сохраняя семантику планировщика, kubelet и API Kubernetes. В Kubernetes v1.37.1 изменены два места: текстовые префиксы версии kubectl и короткие имена Pod в discovery. Linker flags указывают upstream-коммит `f78e722310e50bcaca9276be22276d9e91d91308` и честный статус дерева `dirty`. Скрипт переименования сохраняет copyright, LICENSE и NOTICE.

Группа API — `rknetes.su/v1alpha1`. Семнадцать структурных CRD задают словарь. Наличие CRD само по себе не доказывает работу механизма: действующие операции перечислены в таблице измерений, интерфейсы только со схемой — в BACKLOG.

`rknet-controller` обходит namespace с `rknetes.su/lab=true`. Он сохраняет первоначальные UID и историю IP в ReestrEntry, создаёт deny-политики Cilium, выявляет наследование IP, добавляет `BornBlocked` и учитывает аннотацию о противодействии терроризму. Расширение блокировки использует CIDR наблюдаемого узла, пул вложенного кластера и явно заданную стадию Service API. Отдельный экземпляр контроллера показывает самоотключение; восстановление идёт через адрес гостевой VM вне заблокированного маршрута Service.

ThrottlePolicy применяет настоящую аннотацию полосы Cilium после сопоставления регулярным выражением. WhitelistMode запрещает исходящий трафик, оставляя селекторы разрешённых адресатов и исключение DNS. Проверка целостности анализирует ServiceAccount, образы, ephemeral containers, EndpointSlice и externalIPs. При нарушении блокируется весь разрешённый адресат. Дерево CLI строится по объявленным зависимостям SociallySignificantResource; эти декларации не выдаются за перехваченный трафик.

В опыте с 16 КиБ настоящая tc egress-программа устанавливается в сетевом пространстве выбранного Pod. Она считает TCP payload относительно sequence number, пропускает ACK и отбрасывает данные сверх 16 384 байт. Текущая граница — порт источника 8081 и адресат `10.42.0.0/16`; внешние registry не фильтруются. Проверенный поток с небольшими сегментами получает ровно 16 КиБ. Повторная передача не списывает байты повторно. Произвольные размеры сегментов и подключение через CR вынесены в BACKLOG.

Admission включает 17 validating-вебхуков и один mutating-вебхук. CONNECT-проверки охватывают exec, attach и port-forward; ServiceAccount MAX служит явным исключением для ретрансляции. Доступ через MAX всё равно проверяется клиентским сертификатом и SubjectAccessReview. Maxlet проксирует настоящий upgraded stream и сохраняет байты обоих направлений в JSONL на узле. Этот архив не выдаётся за шестимесячное хранение всего трафика кластера.

Вебхук происхождения определяет registry и явно перечисленные иностранные digest. Вебхук событий отвергает успешные Events без erid. Шлюз watch-office считает действующие watch-запросы к отдельным ConfigMap и закрывает их при превышении порога незарегистрированного объекта. Он возвращает HTTP 451, сохраняет наблюдаемое число и разрешает чтение после регистрации. Порог по умолчанию — 10 000, автоматический тест механизма использует три. Прямой доступ к API существует отдельно от этого явно выбранного шлюза.

Pigeon переносит файлы с полными IPv4/UDP-датаграммами через общий каталог на узле, смонтированный PVC двух namespace. Пакет ждёт 180 секунд; случайный выбор теряет в среднем 55%. Это транспорт через хранилище, а не TUN-интерфейс ядра. Тест проверяет контрольные суммы и неизменность payload при полном запрете сети. Каталог пакетов привязан к UID исходного namespace.

Депонирование копирует настоящие байты TLS Secret в `sorm`. Финализаторы forever удерживают удаляемые Pod. Охлаждение применяет NoExecute только к явно выбранным лабораторным узлам и снимается по времени либо отметке о решённой капче. SovereigntyDrill отключает выбранные иностранные лабораторные адресаты, сохраняя успешный официальный статус. HTTP-сервис Госхрана отдаёт redirect для OCI blob и неизменный индекс Helm с абсолютными иностранными URL; постоянная метрика доступности явно названа официальной.

Профиль conformance сохраняет нативные процессы Kubernetes и установленные ведомства, но не содержит активных лабораторных политик и меток lab у namespace. В namespace conformance не внедряются отказы, API сохраняет настоящую семантику. Успех этого профиля не доказывает соответствие активно разрушающего лабораторного режима.

Некоторые утверждения концепции противоречат Kubernetes. Validating-вебхуки выполняются параллельно: это описано в [документации upstream](https://kubernetes.io/docs/concepts/cluster-administration/admission-webhooks-good-practices/) и измерено на стенде. Kubernetes не даёт CronJob отсутствующее расписание, sidecar — контроль над stdout другого процесса, а RBAC — скрытый объект для неограниченного администратора. BACKLOG фиксирует требуемые замены и критерии приёмки. Исходная концепция сохраняется. [Решения владельца](../OWNER_DECISIONS.ru.md) задают работающие замены: фильтрующий шлюз представления, адаптер первичной записи Postgres, ежегодное расписание с проверкой года и ограниченные эксперименты. Их критерии приёмки остаются в BACKLOG.

Выбранные владельцем замены реализованы отдельными [дополнительными опытами](experiments.ru.md): публичное представление с 451, плашкой и штрафом квоты, ежегодный шестилетний цикл, ограниченная реинвокация и адаптер PostgreSQL. Для проверки 10 001 watch шлюзу временно выделены 2 CPU / 2Gi; затем исходные ресурсы восстановлены. Эта нагрузочная проверка использует штатный порог 10 000 и не заявляет поддержку всех видов ресурсов либо перехват прямого API.
