# Optional regulator experiments

[Русская версия](experiments.ru.md)

These extensions implement the replacements chosen in [owner decisions](../OWNER_DECISIONS.md). They are separate from the native bundle6 and package build3 used for the complete 462/462 conformance run. Each runs in an explicitly labelled lab namespace; the native Kubernetes API retains its normal contract. The [preserved experiment logs](evidence/optional-experiments.tar.gz) contain actual outcomes.

Build them in the tenant builder with `bash /work/src/rknetes/hack/research/build.sh`. Outputs go to `/work/out/optional`; source-file hashes and Go build information go to `/work/evidence/optional-build`. Run a named test using `bash hack/e2e/run.sh UNIQUE-RUN TEST-NAME`. Tests require fresh namespaces, the installed CRDs and the dedicated nested kubeconfig. Remove completed fixtures with `hack/e2e/cleanup.sh` and explicit namespace names.

| Test | Working mechanism and boundary |
|---|---|
| `01-telegram-cycle` | A real annual CronJob uses `0 0 18 6 *` in UTC and a six-year guard relative to 2020. Jobs with controlled years 2027 and 2026 respectively skip and apply a real 1M Cilium bandwidth annotation. Normal execution uses the actual year. Readiness reads ReestrEntry: `🛩` while its block is applied, `ok` after annotation amnesty, both HTTP 200. |
| `08-reinvocation` | A temporary, namespace-selected mutating webhook replaces an image with itself and increments its report counter. A later agency forces one reinvocation. On v1.37.1 the Pod starts with the original image and exactly two reported substitutions; Kubernetes stops the alleged infinite loop. The temporary webhook is removed by the test. |
| `10-presentation` | A verified client certificate and native SubjectAccessReview authorize the explicit public view. It hides the official TunnelProfile, including from the same administrator who reads it through the native API. It redacts prohibited names and logs, decorates output, and fines one explicitly managed 8-CPU namespace quota by 5000m. A real 4-CPU Pod creation is then refused. Its opt-in destructive mode returns HTTP 451 even for discovery; an ordinary native API edit restores the gateway. |
| `09-first-write` | A DataBoundaryPolicy selects an application StatefulSet and its domestic PostgreSQL primary Service. The HTTP adapter commits with synchronous_commit enabled before attempting a separate replica transaction. Data survives primary Pod recreation on its fixed lab volume. A whitelist excluding the primary prevents any replica write while application readiness stays green. A replica-only outage leaves an acknowledged primary commit; retrying the same id completes replication without duplicate rows. |

The log/presentation gateway uses exactly 24 uppercase words and duplicates each Unicode character. With redaction enabled, the measured 200-line sample grew from 2,800 to 152,600 bytes, a factor of 54.5. Allocated file storage grew from 4,096 to 155,648 bytes. These are measured file sizes; no Loki failure is claimed. API presentation uses a JSON envelope containing the disclaimer and object, so it never prefixes invalid text to native Kubernetes JSON.

The incompatible sovereign API experiment runs separately with `hack/research/sovereign-api.sh`. It copies the pinned upstream apimachinery module, renames `pkg/apis/meta/v1` to `pkg/apis/zapreshchyonnaya-v-rf/v1`, and rewrites 114 Go files in that copy. The new package passes its tests and a migrated consumer builds. An unchanged upstream import fails with “does not contain package”. The conformant upstream checkout remains intact.

The first-write adapter exposes one bounded HTTP write operation, not arbitrary PostgreSQL wire-protocol rewriting or atomic transactions across two databases. It uses the [pgx PostgreSQL driver](https://github.com/jackc/pgx) v5.8.0 and parameterized statements. PostgreSQL 17 is pinned to the digest measured by the test. Passwords live only in a lab Secret; logs and evidence contain no credentials. The test retains its small database directories under `/var/lib/rknetes/data-boundary/<namespace UID>` on the selected nested nodes.

These replacements close their measured acceptance criteria. [BACKLOG](../BACKLOG.md) retains the independent requirements for node enrollment, protocol ladders, artifact/log stalls, archive exhaustion and the composed destructive demonstration.

The installed `tspu` DaemonSet now reconciles SovereignBytePolicy using containerd sandbox identity and [TCX links](https://github.com/cilium/ebpf/tree/main/examples/tcx). Its program accounts for sequence wrap and retransmissions, drops whole packets that cross the limit, and permits ACKs and small health requests. Both endpoints must belong to the nested Pod range. Closing the agent closes its unpinned links, so stale filters do not survive a crashed process. [The node-agent evidence](evidence/byte-policy.tar.gz) proves CR attachment, Pod recreation and policy-deletion recovery.

`rknetesctl why --hubble` now joins observed endpoints into a graph rooted at the selected Pod or Service. [The graph test](evidence/dependency-graph.tar.gz) observes a successful first hop and a dropped second hop; unknown observations and cycles remain explicit. This is a graph of observed packet relationships, not proof of request causality or application success.

TLS disclosure for process-generated keys uses an explicit Pod contract: `rknetes.su/tls-disclosure-required=true` and `rknetes.su/key-escrow-secret=<name>`. A missing exported TLS key or missing exact SORM copy sets `RefusedToShareKeys` and creates an escalating ReestrEntry. [The TLS test](evidence/key-refusal.tar.gz) starts a real self-signed HTTPS server with an internal key, observes packet denial, exports those bytes, then requires a separate annotation amnesty. No private key is included in the evidence.

[Whitelist-control evidence](evidence/whitelist-control.tar.gz) records a full real Cilium endpoint policy map: 16,384 entries, ENOSPC from both the kernel and cilium-dbg, with original entries retained. The probe removes only its synthetic high-numbered identities. The controller implements FIFO approval eviction separately, using measured maxEntries minus an explicit reserved budget; the three-resource experiment reserves all but two slots. Periodic WhitelistMode uses the CR creation time as its phase origin and defaults to 60% active time when a period is supplied. The home-node CronJob has a real weekly schedule; only its official annotation calls the schedule classified. Packet timings and actual NoExecute eviction are preserved.

The four 20-second cycles configured 12 seconds active and 8 seconds inactive; packet probes measured a blocked fraction of 0.5569457028551185 (55.7%). Probe timeouts and reconciliation boundaries are included in that observation. The configured duty cycle is not reported as an exactly measured 60%.

[Roaming evidence](evidence/roaming-and-max-first.tar.gz) implements a portable persisted identity contract: machineID,clusterUID,lastSeen and real NodeLease renewTime. A node opts in with a lab label and the exact office namespace UID annotation. [MAX and API-stream evidence](evidence/max-and-api-streams.tar.gz) proves real worker JoinTicket issuance through the optional MAX enrollment gate. The bootstrap control plane is the initial trust anchor; the gate executes before a worker Node or its DaemonSet can exist. An administrator records the worker identity and enrolling certificate CN in the lab office ConfigMap. HTTP403 always denies enrollment. Explicit failure-policy Open permits only transport/5xx unavailability; Closed is the default. The actual Membership containing bootstrap credentials is written0600 under private builder kube storage and never exported.

`max-login` exchanges a TOTP code for a short session bound to the verified client certificate. `hodatay max` consumes `HODATAY_MAX_SESSION_FILE`; native SubjectAccessReview still controls the requested call. Replay, certificate binding and expiry have regression tests; real upgraded exec and expiry have e2e proof. Optional MAX enrollment uses `RK_MAX_ENROLLMENT_SERVER`, `RK_MAX_ENROLLMENT_CA` and `RK_MAX_ENROLLMENT_SESSION` in the stand bootstrap. MAX archives actual Events from every nested namespace privately. Its900000000 scheduling priority applies to Pods with preemption disabled; the host kubelet has no comparable PriorityClass.

The opt-in `--lab-definitions` experiment restricts definition writes to labelled `lab.rknetes.su` CRDs and checks native authorization. A200KB definition and long genuine kubectl logs stall under the same TCX byte mechanism that blocks OCI/Helm. Small discovery requests and application readiness remain green; deleting the policy restores the full log hash and a genuinely Established CRD. MAX discovery paths are bounded so `/apis/...` cannot bypass resource authorization; all impersonation headers are stripped.

[Image-origin evidence](evidence/origin-resolution.tar.gz) uses a real authenticated [Distribution registry](https://distribution.github.io/distribution/about/deploying/). Opt-in ForeignAgentPolicy.resolveDigests reads referenced imagePullSecrets, resolves each current tag with registry HEAD, compares foreignImages and rejects mismatched rewriteImages. The accepted destination is pinned by digest and original provenance is annotated. Explicit registryMirrors let the webhook resolve a node-loopback registry through its actual lab endpoint; insecure endpoints are restricted to nested Pod addresses. Native kubelets ran all three accepted images. The experiment removed its loopback relays and webhook afterward. Resolver code uses go-containerregistry0.20.6, preserving the Cilium1.20.4/ebpf0.22.0 dependency pins.

[National-DNS evidence](evidence/national-dns.tar.gz) uses a real TCP/UDP resolver restricted to `.lab` and nested Pod addresses. Its local domestic answer survives isolation; forwarding to the foreign lab resolver, a real Distribution OCI pull and a real NTP exchange fail. The quarterly CronJob uses `0 3 1 */3 *` in UTC, with per-drill patch permission and a guarded stand-marker read. Its manually triggered60-second Job restores the policy automatically; the normal default duration is300seconds.

`lab-clock` uses the received NTP timestamp as the time source for an actual Go TLS handshake. On NTP failure the test explicitly advances only this application's clock48hours, which rejects a one-day lab certificate on a still-reachable domestic endpoint. A successful NTP resync restores the actual TLS exchange. The experiment changes no host clock, external resolver or external route. DNS scope refusal has regression coverage.
